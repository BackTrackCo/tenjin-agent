Tenjin can now suggest nine free developer tools that run on your machine: ast-grep, Knip, dependency-cruiser, Squawk, Are The Types Wrong?, secretlint (secrets in files), v8r (config files against their SchemaStore schema), oxlint's accessibility rules and type-coverage (hidden `any` types). v8r downloads each file's schema from SchemaStore and sends none of the file, and attw's installed-dependency check fetches that package from the public npm registry. A suggestion comes with a prompt the router reads as one of their tasks, or after your assistant's own shell command, search or edit (a generated migration, a multiline search, a third file edited in one turn, a deprecated dead-code tool, a package packed or published, an import-cycle error, a path a dependency does not export; the four newest come with a prompt alone). Each is one optional line naming a pinned `npx` command this CLI writes, with versions at least 14 days old and install scripts off for all but ast-grep. Your assistant runs it in its own shell under your usual permission prompt. A line shows at most once per tool per agent in a session, and none for a tool it already ran, and only on a platform the tool is qualified on, today macOS on Apple silicon, with `npx` on PATH. The after-call checks run on this machine and ask the router nothing: the command, its output, searches and edited paths never leave it. Once a day the CLI fetches the rule list, sending only how often each rule's line was shown and its tool run. The Codex plugin gains one hook, after a shell command, so it now carries six.

DeepSeek workers can work across a named workspace. With named-directory consent, every named repository is a worker working directory, including for consent saved before this release, and their linked git worktrees are added at job start, so a worker can commit in a sibling checkout. A native additional directory outside consent is withheld from the worker and named in the offer, instead of keeping the work native, and its path is kept out of what Tenjin forwards. Workers get `gh` and git over HTTPS with a per-job GitHub token, read with `gh auth token` or from `TENJIN_WORKER_GITHUB_TOKEN` or `TENJIN_WORKER_GITHUB_TOKEN_FILE` for a narrower token, never from your GitHub config files or keychain. Tenjin replaces the token's value in what it forwards to Tenjin and DeepSeek, in the worker's result and in its activity rows. Worker commands reach GitHub, its content and Actions log hosts, the npm registry and nodejs.org without asking; another host asks in default mode and is denied in auto and bypass mode. On macOS a worker with a token may also reach the system certificate trust service, which `gh` needs. Charges, quotes and settlement are unchanged.

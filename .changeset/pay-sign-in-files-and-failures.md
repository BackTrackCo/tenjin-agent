---
'tenjin-cli': patch
---

`tenjin pay` and the router's job polls answer a seller's own sign-in challenge on a 402 that offers no payment, as the status URL of a paid Monid run does, so a run paid with this version can be collected. They sign only a GET, and only when the challenge matches the responding origin and this wallet paid for it: for a router poll, the wallet that paid its own job; for a direct `tenjin pay`, an earlier payment to that host that names this wallet as its payer. A POST behind a sign-in, a direct one or a job's POST poll, is refused unsigned. They pay nothing on that path, and `--quote` marks such a 402 with `signIn: true`. A run paid with an earlier version has no payment record here, so it is refused, and a record that does not name its payer is refused too (`sign_in_payer_unknown`). A job polled while this machine holds another wallet signs nothing and stays running; the answer names the wallet that paid, and a resume with that wallet collects the result. Each payment, payment record and job now keeps the wallet that signed it (`payer`). A 402 that asks for a Permit2 transfer, or any transfer method other than EIP-3009, is refused before anything is signed, and the refusal names that method: this CLI pays by EIP-3009 only. An imported wallet that had already approved Permit2 could pay a Permit2 seller before; the CLI now refuses those offers. `tenjin pay` saves a binary body (an image, a sound, a PDF) to a file and returns its path in `savedTo` instead of garbled text; `--quote` writes no file. If the downloads folder cannot take the file, it goes to the OS temp folder, and `saveError` says why. If no folder takes it, `bodyBase64` holds the bytes. It also waits for its printed output to reach the reader before it exits, so a large body piped to another program is no longer cut at 64 KB, and a reader that closed early no longer turns the exit code into a crash. Output that cannot be written any other way (a full disk) is said on stderr and exits nonzero, 4 after a payment, with a pointer to `tenjin payments`. A paid call that fails keeps the seller's reason for refusing the payment (`paymentError`) and checks whether it was charged by reading the authorization on the payment's own chain and token (a network with no RPC here, such as Base Sepolia, stays unknown). A call that failed after the chain shows the money taken shows as charged (`settlement: "settled"`), with the seller's reason in `sellerReason`. A seller's payment response that says it settled is only its report: its tx is kept as `reportedTxHash`, and the payment stays unknown until the chain shows it, so reconcile can still release an unused one. Either way an approved quote it ran stays used, even when the seller called the wallet short of funds. A router job whose cut-off submit was taken keeps that on its record, so a failed or resumed ending also says it was charged. Every direct `tenjin pay` that signs is now listed in `tenjin payments`.

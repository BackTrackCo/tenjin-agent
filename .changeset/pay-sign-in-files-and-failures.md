'tenjin-cli': patch
---

`tenjin pay` and the router's job polls answer a seller's own sign-in challenge on a 402 that offers no payment, as the status URL of a paid Monid run does, so a run paid with this version can be collected. They sign only a GET, and only when the challenge names the URL that sent it and this wallet paid for it: a router poll's own job, or, for a direct `tenjin pay`, any earlier payment to that host. A POST behind a sign-in, a direct one or a job's POST poll, is refused unsigned. They pay nothing on that path, and `--quote` marks such a 402 with `signIn: true`. A run paid with an earlier version has no payment record here, so it is refused. `tenjin pay` saves a binary body (an image, a sound, a PDF) to a file and returns its path in `savedTo` instead of garbled text; `--quote` writes no file. It also waits for its printed output to reach the reader before it exits, so a large body piped to another program is no longer cut at 64 KB, and a reader that closed early no longer turns the exit code into a crash. A paid call that fails keeps the seller's reason for refusing the payment (`paymentError`) and reads the authorization on-chain, so a call that failed after the seller took the money shows as charged (`settlement: "settled"`). Every direct `tenjin pay` that signs is now listed in `tenjin payments`.

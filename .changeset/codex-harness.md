'tenjin-cli': patch
---

`tenjin install` sets up Tenjin in Codex too, with no flag. Run by an agent, it sets up the agent it runs in; in a terminal, it sets up Claude Code or Codex, whichever answers `--version`, and asks which when both do, both selected. It records the agents it set up in `installed-hosts.json` in the Tenjin data dir, and `tenjin doctor` and `tenjin uninstall` check or remove each one recorded. `--harness claude|codex` only overrides. For Codex it writes the wallet, the spend limits and the Codex plugin `tenjin` through `codex plugin marketplace add` and `codex plugin add` from the package's `dist/hosts/codex`. Its spend limits follow the same defaults as Claude Code: with no answer the defaults ($0.25 a call, $5 a day) hold and the spend question comes back in `nextSteps`, and `--max-auto-spend` (at least 0.25) and `--session-budget` set your own. The plugin's hooks route your prompt and one web search before it runs and after, its `router` server carries the request tool, named `mcp__router__request`, and a `PermissionRequest` hook allows that tool without a prompt (turn it off in `/hooks` to be asked first). Codex asks you to trust the four hooks in `/hooks`. On native Windows, the CLI starts npm's `codex.cmd` through the script behind it, and the allow hook carries a `commandWindows` form that `cmd.exe` prints as plain JSON. The plugin carries no version, so its hooks keep their trust across `tenjin update`. For Codex, `tenjin doctor` reads Codex's one hook list for the plugin and its trust, and writes nothing, and `tenjin uninstall` removes the plugin and its marketplace.

Every router request now names its host in `harness` (`claude` or `codex`), on the hook, tool and outcome bodies, so the router can leave out a lookup the host's own tools already do.

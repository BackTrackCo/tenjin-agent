The Claude Code plugin now runs on Windows: every command it carries is exec form, `node` and its arguments started with no shell, so Git Bash and PowerShell no longer parse it. The `SessionStart` leg and the `router` MCP server run `node` with the package's own `dist/index.js` (found from `${CLAUDE_PLUGIN_ROOT}` in the shipped plugin, and written as an absolute path into the `skills/tenjin-router/` folder fallback), never the `tenjin` npm shim, which Windows cannot spawn without a shell. The two permission answers are fixed JSON that `node -e` prints. With a `claude` binary present, the `plugin` row now also reads the stamp a session's `SessionStart` leg writes, and warns when no session has started the plugin at this version, since `claude mcp get` runs with doctor's PATH, not Claude Code's. A Claude Code opened before Node was on its PATH writes no stamp, so that row names the cause: its fix is to start a new session and run doctor again, then to run `node --version` in the session and restart Claude Code. A `router server` failure says to restart Claude Code (quit it from the tray) or sign out and in.

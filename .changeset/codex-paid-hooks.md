Codex's automatic hooks route again now that the router charges its routing fee. The Codex plugin's three routing legs (the prompt, and a web call before and after it runs) are `mcp_tool` hooks into the plugin's `router` server, as Claude Code's are, so each leg pays the $0.003 fee from the wallet under the local spend limits, the same way a `request` does. They need Codex 0.149.0 or later: install and update leave an older Codex's plugin copy as it is and say so in one line. Routing keeps working after a prompt edit and under a custom `CODEX_HOME`, which the server now receives through `env_vars`. A fifth hook denies the server's `hook` tool to the assistant. `tenjin install --harness codex` now turns the five hooks on through Codex's app server, the same call `/hooks` makes, for Tenjin's own rows only, and names `/hooks` only when that fails. When the fee cannot be paid, Codex shows why (a low wallet, a locked wallet, the daily limit) once per session, and the status line records `fee unpaid: <reason>` instead of a native choice. `tenjin doctor --harness codex` checks that the routing legs reach the server and that Codex is new enough to run them, with nothing paid or sent. `tenjin update` replaces a Codex plugin copy from an earlier release (only where Codex already has it) and turns its new hooks on; when it cannot, it prints one line and the update still succeeds. `tenjin doctor --harness codex` warns, without failing, while a copy still has the old command legs.

Fix three faults from a live run of two DeepSeek workers accepted together. A worker whose Claude Code announces a tool in the middle of a conversation (an MCP server that connected after its first request, Claude Code 2.1.327) no longer ends at its next model call: the bridge offers that tool and sends no `tool_addition` or `tool_removal` block, which the router refused with 400 `invalid_model_request`. A failed model call now carries the router's own error code in its stop reason. A job no longer ends `unknown` with no cause when the router does not answer its first question inside 3 seconds: the question is asked three times, and a router that never answers ends the job as `not_started` with `endedBy: "router_unreachable"` and the free native repeat. Every job that does not complete keeps its error in its local diagnostic record. The line `Held 2 of 2 Agent calls before native execution.` is no longer written when the parent accepts those offers, so the DeepSeek rows follow Claude Code's own summary directly.

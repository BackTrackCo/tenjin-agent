The `tenjin` Claude Code plugin now carries a mod (Claude Code 2.1.287 or later, terminal and desktop app). Each lookup is one transcript line drawn like a native tool row with its status dot, `⏺ Exa search(best local LLM) · $0.007`; while it runs it reads `Calling Exa search…` with the query under it, as Claude Code shows a running MCP call. A row shows the input only when it names what was looked up (a query, a URL, a name, at most 80 characters), never an image or other media prompt (`⏺ Ideogram V4 · $0.03`), and the state only when it is not a plain success; a lookup is never folded into Claude Code's count line for a run of calls: the count names the other calls only, and each paid lookup draws its own row beneath it. A WebSearch or WebFetch call held for a Tenjin offer shows as its own native row struck through, `~~Web Search~~("best local LLM") · Tenjin offered Exa search`, instead of a red hook error, becomes the lookup's own row once the `request` call runs, and disappears when the model runs the same search natively instead. A paid call shows a toast, and a turn that paid ends with one line: `2 paid lookups, $0.09 · today $0.31 of $5.00`. After an install that created the wallet, the first session shows a toast with its address, and the terminal's prompt hint says the wallet is unfunded until it is funded. The mod allows the request tool after Claude Code's own verdict, so a `deny` or `ask` rule of yours still wins, and keeps it in the prompt's tool list. It reads state under `~/.tenjin` and writes nothing there.

Pay once: a lookup priced over `maxAutoSpend` now asks in Claude Code's dialog (`<label> wants $0.42 for this lookup, over your $0.25 automatic limit. Pay once?`) when the client supports MCP form elicitation. Yes pays that one call at that exact price, and the daily budget, the allowlist, a price cap and the duplicate guard still refuse. No, no answer in five minutes, or a client without the dialog returns `needs_approval` as before, which now carries `policyReason`.

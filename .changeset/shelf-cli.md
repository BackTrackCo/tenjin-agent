A shelf is a name, not a second deployment (shelves/07-build-shelf-cli.md, plus the owner decision of 2026-09-15 that made it one endpoint per action). This is a BREAKING config change and a breaking wire change, and it lands after the server's `shelf-scope` deploy: `publicShelfUrl` and `shelfBypassSecret` are deleted, `shelf` replaces them as the QUALIFIED `<org>/<shelf>` name, and the loop's searches are signed. Run `tenjin install` once after upgrading to sweep the two retired keys, then `tenjin org list` and `tenjin shelf use <org/shelf>`:

- **One question is one HTTP request, to one endpoint.** A prompt, a WebSearch, a WebFetch and a dispatch used to send two requests to two origins, raced in one stage against one budget. There is one now: a signed `POST /api/search` whose body names the shelf, and whose response carries the shelf's candidates AND the marketplace's. There is no per-shelf route: `shelf` is an optional body field on `/api/search` and on `/api/keys/resolve`, so a body without it is byte for byte the public request every existing consumer already sends. The stage's budget is one round trip rather than the slower of two, and the selection between the two sets (`SHELF_RANK`, `better()`) is the same comparison on the same tags it always was. With no shelf set it is one unsigned `POST /api/search`, exactly as before.
- **The ledger shape does not move, and one call can write two rows.** `legs.shelf` keeps its name and its three values, `LOOP_SHAPE` is untouched, and no machine's `loop.db` is rebuilt. What changes is that a `legs` row is a scoped lookup rather than a request, so the shelf call ends with a `team` row and a `public` row, each with its own status, count and outcome. Both carry the ONE call's `elapsed_ms`, so comparing latency across the two rows of a single fire means nothing from here on; the schema says so beside the column.
- **Searches sign with the session key the writes already use.** There is nothing new to log in with and nothing new on disk: a cached `read+write` delegation serves a `read`, so `publish` and `search` share one session file. `lib/search-auth.ts` is the one present-or-mint for the CLI and the daemon, and `read` uses it too, which is what let its `session_origin_mismatch` refusal go — with one origin, a stale file bound to some other host is simply not presentable and re-mints.
- **A credential failure never silences a public answer.** With a shelf set and nothing local able to sign, the call falls back to the unsigned public route, its answer is delivered, and the fire's row carries the reason in its `error` column. In the old shape this was structural, because the public leg was already planned; it is now an explicit branch, which is why it is the first thing tested. `tenjin doctor` names the remedy. A machine with no wallet at all searches public only, which is a valid configuration and not an error.
- **`team.publicFallback` moves from the plan to the request body.** `off` used to drop a planned leg, visible in the plan and in the leg count; it now sets `includePublic: false` and the server returns no public list. The setting, its values and its meaning to a user are unchanged. Anything that reasoned about it by counting legs is now wrong, which is exactly what made it worth saying out loud.
- **`tenjin org` and `tenjin shelf` arrive.** `org list` names the orgs this wallet belongs to, their shelves and each org's public-search policy, and is what a 404 from a shelf lookup actually means: the server answers the same for an unknown org or shelf and for a non-member, by design. `org add|remove <handle|0x>` sends one tagged string and the server resolves it to a creator, minting one for a wallet that has only ever searched. `org set public-search on|off` is the ORG's policy for everyone, distinct from this machine's `team.publicFallback`; the server's off wins. `shelf use <org/shelf>` validates against the shelves the wallet can reach before persisting, because a typo would otherwise look exactly like a membership problem on every later lookup; a bare name is resolved against those orgs and stored qualified, an ambiguous one is refused with the candidates listed, and `--none` clears it. There is no `org create` and no `shelf create`: an operator provisions an org, its first admin and its shelf by script.
- **`tenjin publish` targets the active shelf, free, and `--public` overrides it.** The body carries the qualified `shelf` when one is set; omitted is the marketplace, at the configured default price. The scan tier follows the destination exactly as team mode used to.
- **The team-shelf bypass secret is gone.** `x-vercel-protection-bypass` survives only as a generic preview hook keyed on `TENJIN_PREVIEW_BYPASS` in the environment, never persisted to config and never printed, so the bench and anyone testing a preview deployment can still reach one. It rides ONE origin, named by `TENJIN_PREVIEW_ORIGIN` or by the `TENJIN_BASE_URL` the run was pointed at, and every other host gets nothing: the compare happens in the transport off the request URL, so no call site decides. It pins redirects the way a signed header does, because disclosing it is the harm. Doctor reports the origin it rides to, warns when the key is set with no origin named, and otherwise says nothing.
- **Nothing is inferred from a URL any more.** `isTeamModeConfig`, `isTeamShelfOrigin`, `resolveShelfBypass`, `shelfRouteFor` and `teamOrigin` are deleted: "on a shelf" is `config.shelf !== null`. A `--base-url` on one run no longer silently drops a machine out of team mode, and the skill text, the primer, the failure arm's gate and the publish price all read the same one key.
- **One origin, so `read`, `buy` and `inspect` lose their second-origin allowance**, and `tenjin outcome` loses its routing decision. A shelf piece and a marketplace piece live on the same deployment now, and every close goes to `baseUrl`. `searches.shelf_base_url` is KEPT — it is in `LOOP_SHAPE`, and dropping it would delete every machine's ledger at first open to retire one field — and is now the record of where a search went rather than a route to follow.
- **`tenjin doctor` gains a shelf check and loses the half-wired ones.** It prints the wallet's orgs, their shelves and each policy, and marks whether the configured shelf is among them; it warns when a shelf is set and no session can be presented, naming the one action that clears it. It never mints, the same rule `verifyLocalWallet` holds. The `store` line also carries `team answers delivered, 7d: N`, a join over `legs.outcome = 'hit'`, which counts the team set winning and never a public win over a team miss.

# DeepSeek subagents (draft pilot)

Tenjin can offer DeepSeek V4.1 Flash 1017 for bounded helper work while your parent stays on its original model. All planning stays native, including rewriting an approved plan. Sensitive executable changes, independent deep/security assurance and explicit model/privacy restrictions also stay native. The parent has the final accept/veto choice; an offer alone starts nothing.

Claude Code is the primary host. The worker uses the maintained Claude Agent SDK with your normal project/user settings, MCPs and tool permission rules. It keeps the parent's workspace, including uncommitted changes, and runs with the SDK sandbox. It does not replace the parent's endpoint, credentials or Remote Control. Unsupported custom profiles, isolation requests or permission paths stay native.

The Claude worker preserves the mode observed by the parent's native hook: Manual (`default`), Accept edits, Auto or `dontAsk`. Missing, changed, Plan or bypass modes stay native. Auto uses Claude Code's native client classifier with Flash; explicit ask rules still ask the person. Worker-only model aliases pin helpers and the classifier to Flash. The proxy preserves classifier stop sequences and non-thinking requests while coding turns keep thinking/high. The worker uses Claude's native `[1m]` hint and DeepSeek's recommended compaction threshold; proxy admission remains bounded. This follows [DeepSeek's Claude integration](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/) and [Claude's permission-mode contract](https://code.claude.com/docs/en/permission-modes); it does not change the parent's settings.

Codex retains the router's existing experimental designation, with no extra setting. On qualified Codex 0.167.0-alpha.4.1 hosts, Tenjin holds an independent foreground native spawn with explicit `fork_turns: "none"` and asks the parent to resubmit the complete plaintext assignment. Calls that inherit history, including the default when that option is omitted, stay native. Codex's encrypted message is never decrypted. Tenjin attaches the owned parent context, then the parent accepts or retries native. An accepted job runs inside genuine Codex through its native tools, authenticated MCP connections, command hooks and permission checks. "Approve for me" uses Codex's native Guardian with Flash. Claude tools and settings grant no Codex authority. Unknown policy overlays, unsupported hook types and options, unavailable MCP connections and incomplete parent authority keep the job native before paid routing.

The Codex pilot supports standard user/project configuration. It verifies the parent's recorded local environment and current permission profile, then checks the child's visible tool inventory. Codex does not expose every arbitrary per-thread MCP configuration override in its rollout, so those custom API configurations are outside this qualification. An unloaded parent in a separate app-server is accepted only when the complete owned rollout independently proves the local environment and matching filesystem policy.

## Opt in

Run this only when the person wants this repository's subagent work to reach Tenjin and DeepSeek:

```sh
tenjin config subagents on --repository /path/to/repository --max-job 1
```

The command records version 2 consent for the exact repository, configured router origin, recipients, applicable instructions and total routing/inference ceiling. Version 1 consent keeps work native until the person explicitly enables it again. Routing sends the assignment and bounded parent context to Tenjin and its TypeSafe/Jev processor before the parent accepts an offer. After acceptance, the worker’s applicable native instruction context, assignments and tool results reach DeepSeek through Tenjin. Routing inputs remain the assignment and bounded ordinary parent context; the parent’s final veto preserves known binding constraints. Existing per-call and daily wallet limits still apply. Installing the CLI, turning tool routing on, or having an older native-tier/effort setting is not inference consent. A project can restrict the feature with `router.subagents: false`; it cannot opt anyone in. Known secrets are masked, but sensitive prose is not guaranteed anonymous. Server replay replies are available for 24 hours; expired content is removed by bounded cleanup.

Codex carries its native global/project AGENTS hierarchy into the worker in order, including configured override and fallback filenames. References stay verbatim; the worker follows them through its normal guarded tools. The local snapshot is checked before selection and execution. Complete owned parent metadata supplies the exact base instructions, additional developer authority, default collaboration instructions and runtime workspace roots locally to the child. Unknown, unreadable, changed or oversized authority and unresolved paginated history keep the assignment native. Source reads use native filesystem permission checks and exclude credential files. Claude retains the maintained SDK’s normal automatic global/ancestor/repository CLAUDE, import and scoped-rule loading. These instruction paths grant no extra tool or filesystem permission. The routing envelope remains 16 KB with no new instruction field or extra classification call; full worker authority is never added to Jev's input.

To stop new work:

```sh
tenjin config subagents off
```

The parent calls its native Agent tool normally. Tenjin returns either native continuation or an offer naming DeepSeek, its reason, fees and ceiling. The parent accepts with `subagent({offer_id})` or retries the original native call unchanged. No extra human confirmation is added for the handoff. Normal tool asks and payment limits still apply. An ignored offer starts neither worker. A repeated acceptance cannot start a second worker.

The model router charges once per job: 15% of expected provider spend, capped at $0.003, even when the parent declines a valid paid offer. The inference proxy charges actual reported usage plus 5%. Worker generation and native approval-model requests share one durable job ceiling. Batch settlement collects vouchers later; it does not delay inference. Model routing and inference each use separate SDK channels, salts and storage, isolated from tool routing and scoped to the configured server origin. A local server and production therefore cannot fork one onchain channel, even when the payer and recipient are the same. Model routing keeps the $0.003 fee ceiling and normal routing deposit bounds. Inference uses its quoted reservation under the existing automatic spend policy. A quote can reserve substantially more than the eventual usage charge because it covers provider output exposure.

The `subagent` tool reports the result, elapsed time, actual accounted spend and unresolved reservations. `subagent({cancel: offer_id})` stops and drains an owned worker. Turning the feature off prevents new paid model requests. To stop an active worker and its tools, cancel it or send the host's Interrupt. A timed-out or interrupted purchase remains uncertain until its signed owner-scoped receipt is recovered; Tenjin never buys that turn again automatically. Once the worker is quiescent, the original native task can continue. Codex Interrupt is bound to its turn and uses the native three-second hook limit. Codex does not support SessionEnd MCP hooks; MCP disconnection or SIGTERM drains owned workers. `tenjin balance` and `tenjin status` show remaining model-routing credit separately from inference credit for the current server origin. Each is reused only by its own lane and channel configuration; neither can pay tool-routing fees or calls at another origin. Changing the endpoint leaves the old origin's credit in its SDK storage; switching back makes it visible again.

Earlier local pilot checks covered authenticated MCP flow, allowed/denied/ask actions, cancellation, instruction inheritance and paid file/MCP inference. The genuine Codex/Guardian harness also passed an isolated coding case; that is separate from qualification of the installed routing path. Eleven isolated checks of the actual Claude worker and native SDK passed Auto allow/deny, explicit asks, provider failure, permission changes, provider-settings pinning and the 1M hint using canned inference. These checks establish protocol and permission behavior; they do not grade the classifier or prove a full 1M-token workload. Real Desktop tool-inventory parity still needs its isolated check. Matched frozen worker-capability evaluation and broader activation remain pending. Fable parent testing remains deferred. UI rows may be ordinary MCP rows; quality, time and all-in cost take precedence over cosmetic parity with native subagents.

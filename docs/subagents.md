# DeepSeek subagents (draft pilot)

Tenjin can offer DeepSeek V4.1 Flash 1017 for bounded helper work while your parent stays on its original model. Ordinary implementation and scoped review are eligible. All planning stays native, including rewriting an approved plan, and explicit model/privacy restrictions still bind. The parent uses the repository's instructions, configuration and risk boundaries to accept or veto: a payment, authentication or permission change, review verdict or branch sync is not a universal native-only category. An offer alone starts nothing.

Claude Code is the primary host. The worker uses the maintained Claude Agent SDK with your normal project/user settings, MCPs and tool permission rules. It keeps the parent's workspace, including uncommitted changes, and runs with the SDK sandbox. Independently configured native additional directories remain working directories; native read exceptions remain read exceptions. Naming a repository for disclosure grants neither. It does not replace the parent's endpoint, credentials or Remote Control. Unsupported custom profiles, isolation requests or permission paths stay native. Runtime-only parent directory additions are not captured by the settings resolver.

The Claude worker preserves the mode observed by the parent's native hook: Manual (`default`), Accept edits, Auto or `dontAsk`. Missing, changed, Plan or bypass modes stay native. Auto uses Claude Code's native client classifier with Flash; explicit ask rules still ask the person. Worker-only model aliases pin helpers and the classifier to Flash. The proxy preserves classifier stop sequences and non-thinking requests while coding turns keep thinking/high. The worker uses Claude's native `[1m]` hint and DeepSeek's recommended compaction threshold; proxy admission remains bounded. This follows [DeepSeek's Claude integration](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/) and [Claude's permission-mode contract](https://code.claude.com/docs/en/permission-modes); it does not change the parent's settings.

Codex retains the router's existing experimental designation, with no extra setting. On qualified Codex 0.167.0-alpha.4.1 hosts, Tenjin holds an independent foreground native spawn with explicit `fork_turns: "none"` and asks the parent to resubmit the complete plaintext assignment. Calls that inherit history, including the default when that option is omitted, stay native. Codex's encrypted message is never decrypted. Tenjin attaches the owned parent context, then the parent accepts or retries native. An accepted job runs inside genuine Codex through its native tools, authenticated MCP connections, command hooks and permission checks. "Approve for me" uses Codex's native Guardian with Flash. Claude tools and settings grant no Codex authority. Unknown policy overlays, unsupported hook types and options, unavailable MCP connections and incomplete parent authority keep the job native before paid routing.

The Codex pilot supports standard user/project configuration. It verifies the parent's recorded local environment and current permission profile, then checks the child's visible tool inventory. Codex does not expose every arbitrary per-thread MCP configuration override in its rollout, so those custom API configurations are outside this qualification. An unloaded parent in a separate app-server is accepted only when the complete owned rollout independently proves the local environment and matching filesystem policy.

## Opt in

Run this only when the person wants this repository's subagent work to reach Tenjin and DeepSeek:

```sh
tenjin config subagents on --repository /path/to/repository --max-job 1
```

The command records version 2 consent for the named directory and its descendants, configured router origin, recipients, applicable instructions and total routing/inference ceiling. Repeat it for another repository to retain both; the latest job ceiling applies across the saved list. You can instead explicitly name a workspace directory containing several repositories. Tenjin never infers a parent directory or sibling from a selected repository. Incompatible legacy or other-origin entries are not carried forward. The offer lists the saved disclosure roots separately from the native worker's directory scope. These settings do not grant filesystem access or replace required action approvals.

Version 1 consent keeps work native until the person explicitly enables it again. Routing sends the assignment and bounded parent context to Tenjin and its TypeSafe/Jev processor before the parent accepts an offer. After acceptance, the worker’s applicable native instruction context, assignments and tool results reach DeepSeek through Tenjin. Routing inputs remain the assignment and bounded ordinary parent context; the parent’s final veto preserves known binding constraints. Existing per-call and daily wallet limits still apply. Installing the CLI, turning tool routing on, or having an older native-tier/effort setting is not inference consent. A project can restrict the feature with `router.subagents: false`; it cannot opt anyone in. Known secrets are masked, but sensitive prose is not guaranteed anonymous. Server replay replies are available for 24 hours; expired content is removed by bounded cleanup.

Codex carries its native global/project AGENTS hierarchy into the worker in order, including configured override and fallback filenames. References stay verbatim; the worker follows them through its normal guarded tools. The local snapshot is checked before selection and execution. Complete owned parent metadata supplies the exact base instructions, additional developer authority, default collaboration instructions and runtime workspace roots locally to the child. Unknown, unreadable, changed or oversized authority and unresolved paginated history keep the assignment native. Source reads use native filesystem permission checks and exclude credential files. Claude retains the maintained SDK’s normal automatic global/ancestor/repository CLAUDE, import and scoped-rule loading. These instruction paths grant no extra tool or filesystem permission. The routing envelope remains 16 KB with no new instruction field or extra classification call; full worker authority is never added to Jev's input.

To stop new work:

```sh
tenjin config subagents off
```

The parent calls its native Agent tool normally. Tenjin returns either native continuation or an offer naming DeepSeek, its reason, fees and ceiling. The parent accepts with `subagent({offer_id})` or retries the original native call unchanged. No extra human confirmation is added for the handoff. Normal tool asks and payment limits still apply. An ignored offer starts neither worker. A repeated acceptance cannot start a second worker.

The offer includes the verified saved repository consent and local accept/veto policy. Claude also receives a short local hook-context reminder; the held call reports zero worker usage and cannot be continued as an invented agent. The parent can assess the offer without discovering a deferred tool description. Repository-specific sensitivity and review depth remain the parent's decision with its full context. An unconditional live no-pay instruction, including an unconditional worker paid-tool ban, vetoes a paid offer. Approval before worker tool purchases remains a condition on those purchases, rather than a zero-cost task or model ban. Whole-task or explicit inference, substitution and disclosure restrictions still bind, including missing approvals; settings and caps do not supply approval. No-network rules apply to their actual action and actor scope.

## Continuing a Claude worker

A completed Claude worker returns a private `tenjin-worker-…` handle. The same parent session can send a follow-up through Claude's `SendMessage` tool (`to` and `message`); compatible hosts can also use `Agent`/`Task` with `resume` and `prompt`. Tenjin holds that call and offers the complete follow-up for the parent's acceptance or veto. A held offer's `tenjin-offer-…` identifier is not a worker. Decline a continuation by cancelling its offer; passing a Tenjin handle through native tools cannot resume it. Starting a fresh native worker requires a complete new assignment with the needed context.

Accepted continuations reopen the exact SDK session after the previous process has closed, including across days. Native history remains in the normal Claude config store under its native retention policy; Tenjin runs no idle worker service. The private handle binds the parent session, canonical repository and config directory, SDK session and original paid job. Missing, foreign, active, cancelled or uncertain sessions refuse rather than starting over. Completed acceptances replay their stored answer instead of running twice. Native handles continue through Claude unchanged. Codex worker resume is outside this pilot.

Each continuation reloads current native instructions, user/project/local settings, hooks and MCPs and rechecks disclosure coverage and the parent's permission mode. Its original directory scope remains fixed: changed working directories, read or shell-write exceptions, or revoked disclosure coverage refuse continuation. This preserves the authority attached to the history already retained. Current native instruction and deny-rule updates still apply. It gets a fresh local bridge and token. Native file tools and sandboxed commands cannot read or change Tenjin's registry or native transcript directory. The SDK itself retains access needed for session persistence; configured MCPs retain their native authority. Existing snapshots and native token-based compaction remain enabled.

The original spending ledger, ceiling, used amount and uncertain reservations apply to every continuation, with any lower current ceiling also binding. There is no new Jev call or routing fee. A missing ledger refuses continuation. Unknown paid requests keep their full reservations; an expired server reply cannot authorize buying the request again. Turning subagents off stops further continuations too. This is a foreground handoff; native background-agent panels and notifications are not claimed.

Actual SDK checks across closed processes passed history/compaction preservation, current instruction and Auto-mode loading, normal MCP use, updated permission enforcement and transcript-tool denial. Missing history dispatched no inference. Five scripted actual-parent/mod checks passed accept, cancel, disabled routing, transport failure and ordinary native addressing. A separate three-phase actual-SDK check also passed native sibling Read/Write, file-tool read-exception Write denial, disclosure-only anchor denial and symlink-retarget denial after the production guard. Native Bash controls confirmed existing explicit write restrictions and environment-file protections. Removing sibling disclosure blocked resume before any query, inference or native worker, with history retained. Every process group stopped. These canned-provider checks establish the tested wiring and permission behavior; Fable's routing judgment and real long-context summary quality remain separate evidence.

A small real DeepSeek continuation also recalled a prior fixture value and followed changed native instructions after both activations closed, using the same SDK session, job and cumulative ledger. This direct-credit check qualifies that history/current-rule behavior; production vouchers and durable server authorization are covered separately by the payment and database tests.

The model router requests pinned `jev-1.14.0` once per job with eleven yes/no assessments. Nine work/native-retention checks use .7. Separate held-task and parent-context no-pay checks use .5; either can veto an offer. Missing or malformed answers stay native. Live spending restrictions, including worker paid-tool bans, bind despite saved opt-in; quoted/assistant text and product requirements for free behavior do not create spending bans. The parent still applies its full context and final veto. The current policy matched 106/106 twice under a separate pre-scoring no-pay label layer (40 native / 66 eligible), plus 10/10 synthetic boundaries; all 20 coding assignments were offered. Twenty-three former offers now stay native for live no-pay restrictions; the original labels remain preserved. Earlier nine-question scores did not qualify no-pay behavior. Routing results remain separate from parent acceptance and worker quality.

The model router charges once per job: 15% of expected provider spend, capped at $0.003, even when the parent declines a valid paid offer. The inference proxy charges actual reported usage plus 5%. Worker generation and native approval-model requests share one durable job ceiling. Batch settlement collects vouchers later; it does not delay inference. Model routing and inference each use separate SDK channels, salts and storage, isolated from tool routing and scoped to the configured server origin. A local server and production therefore cannot fork one onchain channel, even when the payer and recipient are the same. Model routing keeps the $0.003 fee ceiling and normal routing deposit bounds. Inference uses its quoted reservation under the existing automatic spend policy. A quote can reserve substantially more than the eventual usage charge because it covers provider output exposure.

The `subagent` tool reports the result, elapsed time, actual accounted spend and unresolved reservations. `subagent({cancel: offer_id})` stops and drains an owned worker. Turning the feature off prevents new paid model requests. To stop an active worker and its tools, cancel it or send the host's Interrupt. A timed-out or interrupted purchase remains uncertain until its signed owner-scoped receipt is recovered; Tenjin never buys that turn again automatically. Once the worker is quiescent, the original native task can continue. Codex Interrupt is bound to its turn and uses the native three-second hook limit. Codex does not support SessionEnd MCP hooks; MCP disconnection or SIGTERM drains owned workers. `tenjin balance` and `tenjin status` show remaining model-routing credit separately from inference credit for the current server origin. Each is reused only by its own lane and channel configuration; neither can pay tool-routing fees or calls at another origin. Changing the endpoint leaves the old origin's credit in its SDK storage; switching back makes it visible again.

Accepted workers have a forty-minute wall budget in addition to the monetary ceiling and cancellation. Claude's native SDK has a 500-turn emergency guard, replacing the ordinary 40-turn cutoff; soft reminders at three, five and eight identical tool calls encourage progress without denying tools. Limit failures include a bounded `stopReason` and turn count when available. A harness limit does not establish a model capability limit, and it does not clear financial uncertainty or authorize buying the turn again.
